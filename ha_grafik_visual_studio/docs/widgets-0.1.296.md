# Studio 0.1.296: verbleibende Widgets

## Deutsch

Die sieben mitgelieferten Pakete Calendar+, Energy, Industrial, Printer, Solar, Technic und Weather/Heating sowie Spezial, Messinstrumente und Datenfluss besitzen eine Widget-Sprache DE/EN/FR. In den Projekteinstellungen bestimmt **Widget-Sprache** den Standard; beim Widget kann die Sprache überschrieben werden. Eigene Texte, Entitäts-IDs und gespeicherte Paket-/Gruppenschlüssel bleiben erhalten. Die allgemeine Studio-Oberfläche bleibt DE/EN. Die bestehenden Paketdateien funktionieren weiter; ein Paketupdate ist nicht nötig.

Beim Technic-Thermostat lässt sich die zunächst deaktivierte Gruppe **Climate-Steuerung** einschalten. Wählen Sie nur die benötigten Funktionen: Heiz-/Kühlbereich, Betriebsart, Voreinstellung, Lüfter, Schwenken, horizontales Schwenken, Soll-Feuchtigkeit und Ein/Aus. Nur vom Gerät gemeldete Funktionen erscheinen. Ein Bereich wird gemeinsam mit „Bereich übernehmen“ gesendet; Grenzen und Schrittweite kommen aus HA. Im Editor, bei Schreibschutz und unbekannten Zuständen wird nichts gesendet. Der bisherige einzelne Sollwert bleibt erhalten; Geräte mit ausschließlich zwei Sollwerten verwenden die Bereichssteuerung. Serviceerfolg bestätigt die Übergabe an HA, keine physische Gerätebestätigung.

Bei lesenden Quellen bietet **HA-Quellen und Einheiten** optional ein Attribut statt des Zustands und automatische Einheitenumrechnung. Leeres Attribut bedeutet Zustand. **Quelle prüfen** aktualisiert die Vorschau, erkennt Attributnamen und zeigt fehlende Quellen, inkompatible Einheiten und strukturierte Daten an. Schreibziele werden nicht umgebogen. Ein Attributeintrag muss zur Datenstruktur des Widgets passen; beliebiges JSON wird nicht automatisch in ein anderes Format übersetzt.

Automatische Umrechnung ist zunächst aus. Bei Energy ersetzt sie für die gewählte Quelle den bisherigen Faktor, ohne ihn zu löschen. Die Zieleinheit fester Anzeigen und Berechnungen folgt der Widget-Einstellung (Solar W/°C/%, Batterieenergie kWh, Climate native Temperatureinheit). Dort ist sie im Quellenfeld gesperrt, damit Summen und Anzeigen zusammenpassen. Frei konfigurierbare Quellen unterstützen W/kW/MW, Wh/kWh/MWh, °C/°F, kompatible Preis-, Längen-, Volumen-, Geschwindigkeits- und Druckeinheiten. Fehlende Metadaten oder inkompatible Einheiten erzeugen einen unbekannten Wert. C/F-Umrechnung mit Offset wird nicht auf Energy-Verläufe angewendet. Unterschiedliche Verlaufsattribute derselben Entität benötigen getrennte Verlaufwidgets.

Energy nutzt weiterhin Recorder-Zustände und keine vollständige native HA-Energieverwaltung/Langzeitstatistik. Dashboard-Einbettung benötigt Browser-Anmeldung, Meteored Internet und Benachrichtigungen ein vorhandenes Ziel. Automatisierte Prüfungen mit simulierten HA-Antworten ersetzen keinen Test mit realen Geräten, Ingress oder Companion.

## English

Calendar+, Energy, Industrial, Printer, Solar, Technic, Weather/Heating, Special, gauges and data flow now offer a DE/EN/FR widget language. **Widget language** in project settings provides the default; each widget may override it. User text, entity IDs and package/group keys are retained. The overall Studio shell remains DE/EN. Existing package files work without a package update.

Enable the optional **Climate controls** group on the Technic thermostat, then select heating/cooling range, HVAC mode, preset, fan, vertical/horizontal swing, target humidity or power. Only capabilities reported by the device appear. Apply both range values together; HA supplies limits and step sizes. Editor mode, read-only widgets and unavailable states cannot send commands. The legacy single target remains available; range-only devices use the range controls. Service success means submission to HA, not physical confirmation.

Optional **HA sources and units** selects an attribute instead of the state and enables compatible unit conversion. An empty attribute means state. **Check source** refreshes the preview, discovers attribute names and reports missing data, incompatible units and structured data. Write targets remain native. Attributes must match the widget’s expected structure; arbitrary JSON is not automatically converted to another schema.

Conversion starts disabled. For an Energy source it replaces the legacy factor without deleting it. Fixed displays/calculations use their widget unit (Solar W/°C/%, battery energy kWh, Climate native temperature unit), with the source target-unit field locked to prevent inconsistent sums/displays. Configurable sources support power, energy, C/F temperature, compatible price, length, volume, speed and pressure units. Missing metadata or incompatible units produce unknown values. Offset-based C/F conversion is not applied to Energy history. Different history attributes of one entity require separate history widgets.

Energy still uses Recorder states rather than the complete native HA Energy dashboard/long-term statistics. Dashboard embedding needs browser authentication, Meteored needs internet, and notifications need a valid target. Mocked automated checks do not replace real-device, Ingress or Companion testing.

## Français

Calendar+, Energy, Industrial, Printer, Solar, Technic, Weather/Heating, Spécial, les jauges et le flux de données proposent une langue de widget DE/EN/FR. **Widget-Sprache** dans les paramètres du projet définit la langue par défaut ; chaque widget peut la remplacer. Les textes personnels, identifiants d’entité et clés de paquet/groupe sont conservés. L’interface générale du Studio reste DE/EN. Les fichiers de paquet existants fonctionnent sans mise à jour.

Activez le groupe facultatif **Commandes climatiques** du thermostat Technic, puis choisissez plage chauffage/refroidissement, mode, préréglage, ventilateur, oscillation verticale/horizontale, humidité cible ou marche/arrêt. Seules les fonctions annoncées par l’appareil apparaissent. Appliquez les deux consignes ensemble ; HA fournit les limites et le pas. L’éditeur, la lecture seule et les états indisponibles ne peuvent pas envoyer de commande. La consigne unique existante est conservée ; les appareils à deux consignes utilisent la commande de plage. Un service réussi confirme la transmission à HA, pas l’état physique.

Le groupe facultatif **Sources et unités HA** choisit un attribut au lieu de l’état et active la conversion compatible. Un attribut vide signifie l’état. **Vérifier la source** actualise l’aperçu, découvre les noms d’attribut et signale les données manquantes, unités incompatibles et données structurées. Les cibles d’écriture restent natives. L’attribut doit correspondre à la structure attendue ; le JSON arbitraire n’est pas converti automatiquement vers un autre schéma.

La conversion est initialement désactivée. Pour une source Energy, elle remplace l’ancien facteur sans le supprimer. Les affichages/calculs fixes utilisent leur unité (Solar W/°C/%, énergie de batterie kWh, unité de température native Climate) ; le champ d’unité cible est verrouillé pour éviter des sommes/affichages incohérents. Les sources configurables acceptent des unités compatibles de puissance, énergie, température C/F, prix, longueur, volume, vitesse et pression. Sans métadonnées ou avec des unités incompatibles, la valeur est inconnue. La conversion C/F avec décalage ne s’applique pas à l’historique Energy. Des attributs historiques différents d’une même entité nécessitent des widgets de suivi séparés.

Energy utilise encore les états Recorder, sans remplacer entièrement le tableau de bord Énergie et les statistiques à long terme de HA. Les tableaux de bord intégrés nécessitent une session navigateur, Meteored internet, et les notifications une cible valide. Les tests automatisés simulés ne remplacent pas les tests sur les appareils réels, Ingress ou Companion.
